Projet MLOps

Prédiction médicale : on prédit si un patient est malade. Mais la réalité change, et si la prédiction n'est ni archivée ni comparée au réel, on ne saura jamais si le modèle a eu raison ni s'il se dégrade. Il faut un modèle fiable et surveillé dans la durée.

L'architecture

patients.csvnettoyage · imputation · encodage
↓
train.py + MLflowcompare, garde best_classifier.pkl
↓
API FastAPI/predict · /confirmer · /patient · /monitoring
↓
Infirmièreprédit + ID
MédecinID + confirme
Monitoringprédit vs réel
↓
predictionssupposition IA
↔ ID ↔
diagnostics_confirmesvérité
↓
PostgreSQLstockage permanent
↓
retrain.pyréentraîne sur la vérité
↓
GitHub Actions → Rendernouveau .pkl, redéploiement

La solution : 4 étapes

01
Entraînement
  • pipeline MLOps complet
  • comparer plusieurs modèles candidats
  • garder le meilleur, tracé dans MLflow
02
Production
  • prédiction archivée dans PostgreSQL
  • comparée au vrai diagnostic du médecin
  • monitoring : a-t-il toujours raison
  • MLflow suit la progression
03
Réentraînement
  • GitHub Actions (cron 6 mois ou manuel)
  • retrain.py lit diagnostics_confirmes
  • réentraîne, MLflow trace
  • nouveau .pkl commit sur GitHub
04
CI/CD
  • les tests se lancent
  • Render reconstruit l'image Docker
  • redéploie l'API
  • le meilleur modèle est resélectionné
